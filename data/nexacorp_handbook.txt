SECTION 2: REMOTE WORK POLICY
================================================================================

2.1 ELIGIBILITY AND AUTHORIZATION
-----------------------------------
All full-time NexaCorp employees are eligible for a hybrid remote work arrangement of up to three days per week, subject to manager approval and role-based access classification. Employees in roles classified as "Critical Infrastructure" — which includes all System Owners listed in Section 1.2 — are required to be physically present in the primary data center office on any day that a planned maintenance window or P1 incident is active, regardless of their standard remote schedule.

Remote work must be performed over the NexaCorp NEXAVPN client (version 3.4.1 or above). Connecting to any NexaCorp internal resource including the NEXACORE-DB, HRPORTAL, BUILDPIPE-CI, or APIGATEWAY-V2 from an unencrypted or non-VPN connection is a Category 2 Security Violation and will result in immediate access suspension pending a review by Priya Nair. The NEXAVPN client must be authenticated via the AUTH-GATEWAY MFA prompt using a registered hardware token (YubiKey 5 Series) or an approved mobile authenticator application.

2.2 HOME NETWORK SECURITY REQUIREMENTS
----------------------------------------
Employees working remotely must ensure their home network meets the following minimum security standards: WPA2 or WPA3 encryption on the wireless network, a router firmware version not older than 18 months from the manufacturer's latest release, and no use of public or shared Wi-Fi without an active NexaCorp NEXAVPN tunnel. NexaCorp IT Security, under Priya Nair's directorate, conducts random endpoint compliance scans on remote devices every 30 days using the NEXASEC-FW integrated endpoint agent. Failures detected during these scans are automatically logged in TICKETSYS and assigned to Kevin Marsh for remediation follow-up.

2.3 REMOTE WORK HARDWARE PROVISIONING
---------------------------------------
All hardware used for remote work must be NexaCorp-issued and enrolled in the Mobile Device Management (MDM) system. Employees who require additional peripherals — monitors, keyboards, docking stations, webcams — must submit a Hardware Procurement Request through the HRPORTAL under the "IT Equipment" service category. Hardware requests up to a value of USD 500 are approved by Kevin Marsh. Requests between USD 500 and USD 2,500 require additional approval from Sarah Jenkins. Any procurement exceeding USD 2,500 must be approved by Anita Sharma and reviewed by Simone Reyes for budgetary compliance.

2.4 INCIDENT RESPONSE DURING REMOTE WORK
------------------------------------------
If a remote employee encounters a suspected security incident — including unusual login activity, unexpected MFA prompts, suspected phishing, or malware indicators — they must immediately disconnect their device from all networks and call the Security Hotline at +1-312-555-0194 (Priya Nair's direct line). Do not attempt to remediate malware independently. Do not send details of suspected incidents via personal email or messaging applications. The official incident reporting channel is TICKETSYS, using the "Security Incident" ticket template, which routes directly to Oliver Pine and Priya Nair for triage.

SECTION 3: SERVER ESCALATION AND INCIDENT MANAGEMENT POLICY
================================================================================

3.1 INCIDENT SEVERITY CLASSIFICATION
--------------------------------------
NexaCorp follows a four-tier incident severity model:

Priority 1 (P1) — Critical: Complete outage of a production system or security breach. Examples include NEXACORE-DB total unavailability, AUTH-GATEWAY complete failure (no users can authenticate), or a confirmed unauthorized intrusion through NEXASEC-FW. P1 incidents must be acknowledged within 15 minutes of detection and resolved or mitigated within 4 hours. P1 escalation immediately involves Sarah Jenkins, Priya Nair, and the relevant System Owner.

Priority 2 (P2) — High: Significant degradation of a production service affecting more than 20% of users. Examples include NEXAVPN latency exceeding 500ms for a sustained period, BUILDPIPE-CI pipeline failures blocking all deployments, or NEXAMAIL relay queue depth exceeding 10,000 messages. P2 incidents must be acknowledged within 30 minutes and resolved within 8 hours.

Priority 3 (P3) — Medium: Non-critical service degradation affecting fewer than 20% of users or a single department. Examples include HRPORTAL session timeouts, APIGATEWAY-V2 rate limiting misconfigurations affecting a single API consumer, or CLOUDSYNC-S3 synchronization lag exceeding 60 minutes.

Priority 4 (P4) — Low: Minor issues, informational alerts, or user-reported cosmetic bugs. Examples include MONITORX dashboard display errors, non-urgent hardware replacements, or password reset requests.

3.2 ESCALATION PATHS BY SYSTEM
---------------------------------
AUTH-GATEWAY incidents (error codes beginning with ERR-AUTH-*): Primary contact is Marcus Thompson. If Marcus is unavailable within 15 minutes on a P1, escalate to Sarah Jenkins at sarah.j@nexacorp.com or +1-312-555-0188.

Emergency changes (required within less than 72 hours due to security patches or active incident mitigation) require verbal approval from Sarah Jenkins and Priya Nair, followed by a retroactive TICKETSYS Change Request within 24 hours.

SECTION 5: DATA CLASSIFICATION AND HANDLING POLICY
================================================================================

5.1 DATA CLASSIFICATION TIERS
--------------------------------
NexaCorp classifies all data into four tiers:

Tier 1 — Public: Information approved for public release. No access controls required beyond standard authentication.
Tier 2 — Internal: General business data for use by all employees. Must not be shared with external parties without approval from Simone Reyes.
Tier 3 — Confidential: Sensitive business data including financial records, HR data, client contracts, and security configurations. Access is role-based and audited quarterly by Priya Nair. Tier 3 data must be encrypted at rest (AES-256) and in transit (TLS 1.2 minimum).
Tier 4 — Restricted: Highly sensitive data including PII, credentials, cryptographic keys, and regulatory audit records. Access requires multi-factor authentication via AUTH-GATEWAY and explicit approval from Priya Nair. All access to Tier 4 data is logged in MONITORX with 90-day retention.

5.2 PERSONALLY IDENTIFIABLE INFORMATION (PII) HANDLING
---------------------------------------------------------
NexaCorp collects, processes, and stores PII as defined under GDPR, CCPA, and applicable regional regulations. All PII — including employee names, email addresses, phone numbers, national identification numbers, health records, and financial data — is classified as Tier 4 Restricted. PII stored in NEXACORE-DB is encrypted using column-level encryption managed by Farida Hassan. PII in HRPORTAL is subject to Workday's data processing agreement and reviewed annually by Lena Kovacs and Simone Reyes. Any suspected PII breach must be reported to Priya Nair at p.nair@nexacorp.com or +1-312-555-0194 within 1 hour of discovery. NexaCorp's regulatory obligation requires notification to supervisory authorities within 72 hours of confirming a PII breach.

5.3 DATA RETENTION AND DELETION
---------------------------------
Operational logs from MONITORX, NEXASEC-FW, AUTH-GATEWAY, and BUILDPIPE-CI are retained for 90 days in hot storage and 365 days in NEXABACKUP cold storage. NEXACORE-DB transactional data is retained per contractual and regulatory requirements, with a default retention period of 7 years unless a customer data deletion request is received. HR data in HRPORTAL is retained for the duration of employment plus 5 years, as required by applicable labor regulations. Farida Hassan and Simone Reyes jointly review and execute data deletion schedules on a quarterly basis. All deletion activities are logged in TICKETSYS under "Data Governance" category.

SECTION 7: INFORMATION SECURITY POLICY

7.1 PASSWORD AND CREDENTIAL MANAGEMENT
-----------------------------------------
All NexaCorp employees must use the enterprise password manager (HashiCorp Vault, managed by Priya Nair) for storing system credentials, API keys, and service account passwords. Personal credentials must not be stored in plain text, in code repositories, or in shared drives. Any authentication failure generating error code ERR-AUTH-9092 indicates an expired or revoked MFA token and must be resolved by contacting Marcus Thompson. Error code ERR-AUTH-8801 indicates a certificate mismatch on the AUTH-GATEWAY and must be escalated directly to Marcus Thompson as a P2 incident.

7.4 PENETRATION TESTING AND VULNERABILITY MANAGEMENT

SECTION 8: DATABASE ACCESS AND QUERY POLICY
================================================================================

8.1 NEXACORE-DB ACCESS GOVERNANCE
------------------------------------
Access to NEXACORE-DB is strictly controlled and governed by a Role-Based Access Control (RBAC) model maintained by Derek Walsh. There are four defined database roles:

DBA_ADMIN: Full DDL and DML access. Assigned only to Derek Walsh and Farida Hassan.
DBA_READ_WRITE: DML access to specific schemas. Assigned to application service accounts and Raj Patel for development schema.
DBA_READ_ONLY: SELECT-only access to non-PII schemas. Assigned to analytics and reporting service accounts.
DBA_AUDIT: Access to audit log tables only. Assigned to Simone Reyes for compliance queries.

All access provisioning requests must be submitted in TICKETSYS and approved by both Derek Walsh and Priya Nair. Access is reviewed quarterly; unused accounts are disabled automatically after 45 days of inactivity by Farida Hassan's automated cleanup scripts.

8.2 QUERY PERFORMANCE AND TIMEOUT POLICY
------------------------------------------
Queries executing for more than 300 seconds are automatically terminated by NEXACORE-DB's Oracle Resource Manager. This generates error code DB-TIMEOUT-404X in the application log and must be investigated by Derek Walsh or Farida Hassan. Long-running queries that are business-critical can be temporarily whitelisted for up to 7 days by Derek Walsh, with notification to Sarah Jenkins. Error code DB-LOCK-1192X indicates a deadlock condition and triggers an automated alert to Derek Walsh via MONITORX/PagerDuty. Error code DB-CONN-POOL-99 indicates connection pool exhaustion and must be resolved within 30 minutes as it typically escalates to a P1 incident if not mitigated.

8.3 BACKUP AND RECOVERY PROCEDURES
-------------------------------------
NEXACORE-DB is backed up under the following schedule managed by Farida Hassan:
- Full backup: Every Sunday at 01:00 CST, stored locally and replicated to NEXABACKUP cold storage.
- Incremental backup: Daily Monday–Saturday at 01:00 CST.
- Redo log archiving: Continuous, with 30-minute flush cycles.

Recovery Time Objective (RTO) for NEXACORE-DB: 4 hours. Recovery Point Objective (RPO): 30 minutes. Any backup failure generates error code BACKUP-CHKSUM-77Z, which alerts Farida Hassan via MONITORX. If two consecutive backups fail, a P2 incident is automatically created in TICKETSYS. Quarterly restore drills must be documented and countersigned by Derek Walsh and Simone Reyes.

9.2 CLOUDSYNC-S3 OPERATION
-----------------------------
The CLOUDSYNC-S3 system synchronizes NexaCorp on-premise file shares to AWS S3 on a 15-minute schedule. Synchronization failures generate the following error codes:
- SYNC-FAIL-2201B: General sync failure; indicates network or credential issue.
- SYNC-DELTA-441C: Delta computation failure; indicates a corrupted manifest file.
- SYNC-HASH-773B: Hash verification failure; indicates file corruption during transfer.

Error SYNC-FAIL-2201B must be resolved by Chloe Fontaine within 2 hours as prolonged sync failure can result in data loss exposure. All SYNC errors are monitored in MONITORX and alert Chloe Fontaine via PagerDuty.

9.3 COST MANAGEMENT AND TAGGING POLICY
----------------------------------------

Resources untagged for more than 14 days are eligible for automatic termination after a 48-hour grace period notification, per Chloe Fontaine's cloud hygiene automation.

11.3 POLICY EXCEPTIONS
------------------------
Policy exceptions must be submitted in writing to both Priya Nair and Simone Reyes, with a risk assessment and proposed compensating controls. Exceptions are valid for a maximum of 90 days and must be re-evaluated and re-approved at expiry. All active exceptions are tracked in a policy exception register maintained by Simone Reyes.

SECTION 12: ACCEPTABLE USE POLICY
================================================================================

12.1 CORPORATE ASSETS
------------------------
NexaCorp-issued hardware and software licenses are for business use. Incidental personal use is permitted provided it does not: violate any law, consume significant system resources, introduce security risk, or conflict with NexaCorp's Code of Conduct. The NEXASEC-FW deep packet inspection module (managed by Oliver Pine) monitors all traffic on the corporate network for policy violations. Employees found to be using NexaCorp systems for activities including but not limited to illegal downloads, cryptocurrency mining, accessing adult content, or intentional data exfiltration will face immediate suspension and potential termination, subject to review by Lena Kovacs and Anita Sharma.

12.2 SOFTWARE INSTALLATION POLICY
------------------------------------
Only software from the NexaCorp approved software catalog — managed by Kevin Marsh — may be installed on NexaCorp-issued devices. Employees may not install unapproved software, browser extensions, or OS modifications. Requests to add software to the approved catalog must be submitted in TICKETSYS, reviewed by Oliver Pine for security impact, and approved by Kevin Marsh. All approved software is distributed via the BUILDPIPE-CI-integrated Endpoint Management system, which ensures software is version-locked and signed.

12.3 DATA EXFILTRATION CONTROLS
---------------------------------
Transmission of Tier 3 or Tier 4 data to external systems — including personal email, personal cloud storage (Dropbox, Google Drive personal accounts), or USB devices — is strictly prohibited without explicit written authorization from Priya Nair and Simone Reyes. NEXASEC-FW enforces DLP (Data Loss Prevention) policies that block unauthorized transfer of patterns matching known PII formats, financial data schemas, or classified document headers. Triggered DLP events generate error code FW-DROP-3341 and alert Oliver Pine and Priya Nair immediately.

SECTION 13: BUILDPIPE-CI AND DEVOPS POLICY
================================================================================

13.1 PIPELINE GOVERNANCE
--------------------------
All code deployments to ZONE-PROD must pass through BUILDPIPE-CI. Manual deployments to production without a pipeline run are prohibited and constitute a Category 1 Security Violation. BUILDPIPE-CI is configured with the following mandatory gates: static code analysis (SonarQube), dependency vulnerability scan (Dependabot/Snyk), unit test coverage minimum 80%, integration test pass rate 100%, and manual approval gate for production deployments approved by Nathan Xu or his designate.

13.2 DOCKER AND CONTAINER POLICY
-----------------------------------
All containerized workloads must use base images from the NexaCorp-approved Docker registry maintained by Nathan Xu. Use of public Docker Hub images in production is prohibited unless specifically approved by Priya Nair. Container images must be scanned by Trivy before registry push; images with Critical severity CVEs are blocked from being pushed. Error code BUILD-DOCKER-55X indicates a Trivy-blocked image push and requires Raj Patel (or the submitting developer) to remediate the vulnerability before re-attempting the push.

13.3 SECRET MANAGEMENT IN CI/CD
---------------------------------
Secrets (API keys, database credentials, TLS certificates) must never be hardcoded in repository code or pipeline definitions. All secrets must be injected at runtime via HashiCorp Vault integration (managed by Priya Nair) or via BUILDPIPE-CI's native secret store (managed by Nathan Xu). Violation of this policy — including committing credentials to any NexaCorp repository — triggers an automatic TICKETSYS P1 security incident assigned to Oliver Pine and Priya Nair.

================================================================================
SECTION 14: APIGATEWAY-V2 AND DEVELOPER API POLICY
================================================================================

14.1 EXTERNAL API GOVERNANCE
------------------------------
All external-facing API endpoints served through APIGATEWAY-V2 must be documented in the NexaCorp Developer Portal (managed by Raj Patel) and versioned under the NexaCorp API Versioning Standard (major.minor format). API deprecation requires a minimum 6-month notice period and communication via NEXAMAIL developer newsletter.

14.2 RATE LIMITING AND THROTTLING
-----------------------------------
APIGATEWAY-V2 enforces rate limits on all external consumers. Default limits are 1,000 requests per minute per API key. Exceeding rate limits generates error code API-RATE-4429 (HTTP 429 Too Many Requests) returned to the consumer. Requests for higher rate limit tiers must be submitted to Raj Patel, approved by Chloe Fontaine, and reviewed by Simone Reyes for data volume compliance implications.

14.3 JWT VALIDATION AND API SECURITY
--------------------------------------
All external API requests must be authenticated using short-lived JWT tokens issued by AUTH-GATEWAY (managed by Marcus Thompson) and validated at the APIGATEWAY-V2 layer. Tokens expire after 15 minutes. Error code API-TIMEOUT-7720 indicates a token validation failure due to expiry or signature mismatch and is logged in MONITORX. Repeated API-TIMEOUT-7720 events from the same consumer key may indicate a compromised key and will trigger an automatic TICKETSYS security alert assigned to Oliver Pine.
